# 클로드 태그 예시 프롬프트

책 10.2절의 대표 장면을 팀 상황에 맞게 바꿔 쓸 수 있도록 모았습니다.
실제 채널에서는 연결된 도구와 권한에 따라 가능한 작업이 달라집니다.

## 1. 배포 후 오류 원인 조사

```
@Claude 오늘 오후 3시 배포 뒤로 결제 페이지 오류가 늘었습니다. 무엇이 바뀌었는지, 의심되는 원인이 무엇인지 정리해주세요.
```

더 구체적으로 맡기고 싶다면:

```
@Claude 오늘 오후 3시 배포 이후 결제 페이지 오류가 늘었습니다.
1. 배포에 포함된 변경 사항
2. 오류가 늘어난 시점
3. 먼저 확인할 가설
4. 사람이 직접 검증해야 할 항목
으로 나눠 정리해주세요.
```

## 2. 지표를 묻고 표로 받기

```
@Claude 지난주 신규 가입자 수를 요일별로 정리해주세요. 전주와 비교해서 표로 보여주면 좋겠습니다.
```

보고용 초안이 필요하다면:

```
@Claude 지난주 신규 가입자 수를 요일별로 전주와 비교해주세요.
표 아래에는 증가 또는 감소가 눈에 띄는 요일과 추가로 확인할 질문을 3개 적어주세요.
```

## 3. 채널 논의를 결정 기록으로 남기기

```
@Claude 위에서 오간 가격 정책 논의를 읽고, 무엇으로 결정됐는지와 남은 과제를 정리해주세요.
```

담당자와 기한까지 분리하고 싶다면:

```
@Claude 이 스레드의 논의를 결정된 것, 남은 과제, 담당자 미정 항목으로 나눠 정리해주세요.
담당자나 기한이 명확하지 않으면 임의로 채우지 말고 "확인 필요"라고 표시해주세요.
```

## 4. 루틴 걸어두기

```
@Claude 매일 오전 9시(한국 시간)에 이 채널의 열린 스레드를 확인하고 항목마다 상태를 한 줄씩 올려주세요.
```

루틴 확인과 중지는 이렇게 요청합니다.

```
@Claude 이 채널에 어떤 루틴이 걸려 있나요?
```

```
@Claude 매일 오전 9시에 열린 스레드를 요약하는 루틴을 멈춰주세요.
```

## 사용 전 확인

- 채널 구성원이 결과를 함께 봐도 되는 작업인지 확인합니다.
- 클로드가 접근할 수 있는 도구와 데이터 범위를 먼저 확인합니다.
- 보고나 의사결정에 쓸 숫자는 원본 시스템과 대조합니다.
- 장애나 비용처럼 중요한 판단은 클로드의 정리를 사람 검토의 출발점으로만 씁니다.
