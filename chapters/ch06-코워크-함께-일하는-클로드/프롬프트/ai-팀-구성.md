# AI 팀을 만들어 일 나누기

책 6.3.6절의 내용입니다. 작업이 길어지고 품질 기준이 높아지면
사람 조직이 역할을 나누듯 목적이 다른 여러 에이전트를 만들어 협업하게 합니다.

> 먼저 하나의 프로젝트 안에서 구성하세요. 프로젝트 범위가 같아야 에이전트마다 같은 맥락을 반복 설명하지 않아도 됩니다.

## 에이전트를 구성하는 네 가지 요소

| 요소 | 설명 |
| --- | --- |
| 역할 | 무슨 일을 하는가. "무엇이든 하는 AI"보다 "콘텐츠 리서치를 전담하는 AI"처럼 구체적일수록 좋습니다. |
| 지침 | 어떻게 일할지. 단계별 절차, 품질 기준, 출력 형식을 명시합니다. |
| 도구 | 접근할 수 있는 것들. 웹 검색, 로컬 폴더, 커넥터 범위가 행동 범위를 결정합니다. |
| 메모리 | 프로젝트 안에서 이전 작업 맥락과 선호를 축적합니다. |

## 콘텐츠 프로덕션 4인 팀

| 에이전트 | 역할 | 입력 | 출력 폴더 |
| --- | --- | --- | --- |
| Research Agent | 하위 주제·핵심 사실·인사이트 정리 | 주제 키워드 | `/Research` |
| Outline Agent | 제목·섹션 구성·분량·도입·마무리 작성 | 리서치 브리프 | `/Outlines` |
| Writer Agent | 본문 초안 작성 | 개요 | `/Drafts` |
| Editor Agent | 사실 정확성·흐름·톤·중복 점검 | 초안 | `/Published` |

## Research Agent 시스템 프롬프트

```
당신은 콘텐츠 리서치 에이전트입니다.
주제를 받으면 아래 순서를 따릅니다.

1. 가장 중요한 하위 주제 5개를 먼저 찾습니다.
2. 각 하위 주제마다 핵심 사실, 통계, 전문가 의견을 정리합니다.
3. 서로 상충하는 주장이나 논쟁 지점을 찾아 별도로 표시합니다.
4. 마지막에 "핵심 인사이트" 섹션에 실전에서 바로 쓸 수 있는 인사이트 3~5개를 정리합니다.
5. 결과물을 [주제명]-research.md 파일로 /Research 폴더에 저장합니다.

품질 기준: 구체적인 수치와 출처를 우선합니다.
불확실한 정보는 "확인 필요"로 표시하고 단언하지 않습니다.
```

단일 요청으로 충분한 작업이라면 [실전 워크플로우](실전-워크플로우.md)부터 시작하세요.
