# AI 팀을 만들어 일 나누기

『클로드 활용 입문서』 6.3.6절(예제 6.12)의 내용입니다. 작업이 길어지고 품질 기준이 높아지면,
사람 조직이 역할을 나누듯 **목적이 다른 여러 에이전트를 만들어 협업**하게 합니다. 각 에이전트는
한 가지 일에만 집중하고, 자신의 결과물을 다음 에이전트에게 넘깁니다.

> **💡 먼저 하나의 프로젝트 안에서 구성하세요.** 코워크의 메모리는 프로젝트 범위에서만 유지됩니다.
> 세션을 프로젝트로 묶으면 에이전트마다 같은 맥락을 반복 설명하지 않아도 되고, 이전 작업 흐름이 이어집니다.
> (여기서 말하는 '팀'은 6.3.3절에서 코워크가 한 작업 안에서 자동으로 나눠 돌리는 서브 에이전트와는 다릅니다.)

---

## 에이전트를 구성하는 네 가지 요소 (표 6.3)

| 요소 | 설명 |
| --- | --- |
| 역할 | 무슨 일을 하는가. "무엇이든 하는 AI"가 아니라 "콘텐츠 리서치를 전담하는 AI"처럼 구체적일수록 좋습니다. |
| 지침 | 어떻게 일할지. "리서치해주세요" 한 줄보다 단계별 절차·품질 기준·출력 형식을 명시할수록 안정됩니다. |
| 도구 | 실제로 접근할 수 있는 것들(웹 검색, 로컬 폴더, 커넥터). 도구 범위가 행동 범위를 결정합니다. |
| 메모리 | 프로젝트 안에서 이전 작업 맥락과 선호를 축적. 프로젝트 밖 독립 세션끼리는 유지되지 않습니다. |

## 콘텐츠 프로덕션 4인 팀 (표 6.4)

핸드오프 흐름은 **Research → Outline → Writer → Editor**이며, 각 에이전트의 출력이 다음 에이전트의 입력이 됩니다.

| 에이전트 | 역할 | 입력 | 출력 폴더 |
| --- | --- | --- | --- |
| Research Agent | 하위 주제·핵심 사실·인사이트를 정리한 리서치 브리프 작성 | 주제 키워드 | /Research |
| Outline Agent | 제목·섹션 구성·분량·도입·마무리를 포함한 개요 작성 | 리서치 브리프 | /Outlines |
| Writer Agent | 본문 작성(단락 3문장 이하, 핵심 볼드, 숫자·예시 포함) | 개요 | /Drafts |
| Editor Agent | 사실 정확성·흐름·톤·중복 점검 후 최종본으로 다듬기 | 초안 | /Published |

## Research Agent 시스템 프롬프트 (예제 6.12)

코워크 프로젝트 안에서 새 세션을 열고, 아래를 **시스템 지침**으로 입력하면 역할이 고정됩니다.
나머지 세 에이전트도 같은 방식으로 역할·지침·입출력 폴더만 바꿔 구성하면 됩니다.

```
당신은 콘텐츠 리서치 에이전트입니다.
주제를 받으면 아래 순서를 따릅니다.

1. 가장 중요한 하위 주제 5개를 먼저 찾습니다.
2. 각 하위 주제마다 핵심 사실, 통계, 전문가 의견을 정리합니다.
3. 서로 상충하는 주장이나 논쟁 지점을 찾아 별도로 표시합니다.
4. 마지막에 "핵심 인사이트" 섹션에 실전에서 바로 쓸 수 있는 인사이트 3~5개를 정리합니다.
5. 결과물을 [주제명]-research.md 파일로 /Research 폴더에 저장합니다.

품질 기준: 구체적인 수치와 출처를 우선합니다.
불확실한 정보는 "확인 필요"로 표시하고 단언하지 않습니다.
```

> 이 틀을 익히면 자신의 업무에 맞는 팀 구성(예: 리서치 → 분석 → 슬라이드 → 검수)을 스스로 설계할 수 있습니다.
> 단일 요청으로 충분한 작업이라면 → [실전 워크플로우](실전-워크플로우.md)로 시작하세요.
