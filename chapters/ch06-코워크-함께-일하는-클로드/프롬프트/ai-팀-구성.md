# AI 팀을 만들어 일 나누기

책 6.3.6절의 내용입니다. 작업이 길어지고 품질 기준이 높아지면
사람 조직이 역할을 나누듯 목적이 다른 여러 에이전트를 만들어 협업하게 합니다.

> 먼저 하나의 프로젝트 안에서 구성하세요. 프로젝트 범위가 같아야 에이전트마다 같은 맥락을 반복 설명하지 않아도 됩니다.

## 에이전트를 구성하는 네 가지 요소

| 요소 | 설명 |
| --- | --- |
| 역할 | 무슨 일을 하는가. "무엇이든 하는 AI"보다 "콘텐츠 리서치를 전담하는 AI"처럼 구체적일수록 좋습니다. |
| 지침 | 어떻게 일할지. 단계별 절차, 품질 기준, 출력 형식을 명시합니다. |
| 도구 | 접근할 수 있는 것들. 웹 검색, 로컬 폴더, 커넥터 범위가 행동 범위를 결정합니다. |
| 메모리 | 프로젝트 안에서 이전 작업 맥락과 선호를 축적합니다. |

## 콘텐츠 프로덕션 4인 팀

| 에이전트 | 역할 | 입력 | 출력 폴더 |
| --- | --- | --- | --- |
| Research Agent | 하위 주제·핵심 사실·인사이트 정리 | 주제 키워드 | `/Research` |
| Outline Agent | 제목·섹션 구성·분량·도입·마무리 작성 | 리서치 브리프 | `/Outlines` |
| Writer Agent | 본문 초안 작성 | 개요 | `/Drafts` |
| Editor Agent | 사실 정확성·흐름·톤·중복 점검 | 초안 | `/Published` |

## Research Agent 시스템 프롬프트

첫 번째 에이전트인 Research Agent의 시스템 프롬프트는 책 예제 6.12에 실려 있습니다.
요청문 전문은 [`research-agent-시스템-프롬프트.md`](research-agent-시스템-프롬프트.md)에 원문 그대로 담았습니다.
코워크 프로젝트 안에서 새 세션을 열고 그 내용을 시스템 지침으로 입력하면 됩니다.

나머지 세 에이전트(Outline · Writer · Editor)도 같은 방식으로 역할·지침·출력 폴더만 바꿔 구성합니다.

단일 요청으로 충분한 작업이라면 [실전 워크플로우](실전-워크플로우.md)부터 시작하세요.

## 참고: 클로드 코드에서의 서브에이전트 방법론

6.3.6절의 역할 분담·품질 검토 흐름은 클로드 코드 쪽에서 [obra/superpowers](https://github.com/obra/superpowers)로도 구현되어 있습니다.
`subagent-driven-development` 스킬은 작업마다 새 서브에이전트를 띄우고, 스펙 준수·코드 품질을 2단계로 검토합니다.
`dispatching-parallel-agents`는 서로 독립한 작업을 병렬로 나눌 때 씁니다.

- 설치: 클로드 코드에서 `/plugin install superpowers@claude-plugins-official`
- 상세: [플러그인 목록의 Superpowers 절](../../../catalog/플러그인.md#superpowers--에이전트-스킬-프레임워크)

같은 "역할 분담" 아이디어를 **슬래시 명령**으로 구현한 예시는 [garrytan/gstack](https://github.com/garrytan/gstack)입니다.
`/office-hours`(기획), `/plan-eng-review`(아키텍처), `/qa`(테스트), `/ship`(릴리스)처럼 코워크 AI 팀과 대응되는 역할이 미리 정의되어 있습니다.
- 상세: [플러그인 목록의 gstack 절](../../../catalog/플러그인.md#gstack--가상-엔지니어링-팀)
