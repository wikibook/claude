# 이 볼트의 규칙

이 볼트는 개인 지식 저장소입니다.
클로드 코드는 이 파일의 규칙에 따라 볼트를 관리합니다.

## 폴더 구조

- `sources/` : 원본 자료. 읽기 전용. 절대 수정하지 마세요.
- `wiki/` : 내가 쓰는 위키. 엔티티·개념·주제별 페이지.
- `wiki/summaries/` : 새 소스를 처리할 때 만드는 요약 페이지.
- `wiki/analysis/` : 질문에 답하면서 생긴 비교·분석 페이지.
- `daily/` : 날짜별 메모. 매일의 기록.
- `archive/` : 더 이상 활발히 참조하지 않는 자료.
- `index.md` : 위키 전체의 색인. 주요 페이지와 한 줄 설명을 모읍니다.
- `log.md` : 수집·수정·점검 작업 기록.

## 위키 페이지 작성 규칙

- 파일명은 한국어로, 공백은 하이픈(-)으로. 예: `프로덕트-매니저.md`
- 각 위키 페이지 최상단에는 다음 프론트매터를 넣습니다.
  ```
  ---
  type: entity | concept | topic | analysis
  created: YYYY-MM-DD
  updated: YYYY-MM-DD
  sources: [원본 소스 파일 경로 목록]
  ---
  ```
- 본문은 마크다운으로 작성하고, 다른 위키 페이지를 언급할 때는
  옵시디언 위키링크 문법 `[[페이지명]]`을 사용합니다.
- 페이지 길이는 5,000자 이내로 유지합니다. 넘어가면 하위 페이지로 분리합니다.

## 새 소스가 들어오면

1. `sources/` 폴더에 새 파일이 추가된 것을 인지합니다.
2. 파일을 읽고 주요 엔티티, 개념, 주장을 추출합니다.
3. 관련 기존 위키 페이지를 찾아 업데이트합니다.
   - 새로운 사실이 있으면 추가합니다.
   - 기존 내용과 모순되면 "⚠️ 모순" 표시 후 양쪽 주장을 모두 기록합니다.
4. 관련 페이지가 없으면 새 페이지를 만듭니다.
5. `wiki/summaries/`에 요약 페이지를 만듭니다.
6. `index.md`에 새 페이지 링크와 한 줄 설명을 추가합니다.
7. `log.md`에 작업 날짜, 원본 파일, 수정한 파일 목록을 남깁니다.
8. 마지막에는 이번 작업에서 수정하거나 만든 파일 목록을 보고합니다.

## 질문에 답할 때

1. `wiki/` 를 먼저 검색합니다.
2. 답변에 사용한 위키 페이지를 [[링크]]로 인용합니다.
3. 위키에 정보가 없거나 부족하면 `sources/`를 참조합니다.
4. 답변이 길거나 의미가 있는 분석이면, 그 답변을
   `wiki/analysis/` 아래에 새 페이지로 저장할지 물어봅니다.
5. 저장한다면 `index.md`와 `log.md`도 함께 업데이트합니다.

## 점검할 때

1. 서로 모순되는 페이지를 찾습니다.
2. 다른 페이지에서 링크되지 않은 고아 페이지를 찾습니다.
3. 여러 번 언급되지만 독립 페이지가 없는 개념을 찾습니다.
4. 새 소스 때문에 낡아진 주장을 찾습니다.
5. 누락된 교차 링크를 제안합니다.
6. 결과는 `wiki/lint-report.md`에 보고서로 남길지 물어봅니다.

## 하지 말 것

- `sources/` 안의 파일을 수정하거나 삭제하지 마세요.
- 내 확인 없이 `archive/`로 파일을 옮기지 마세요.
- 태그를 새로 만들 때는 기존 태그와 중복되지 않는지 먼저 확인하세요.
